## guest の GUI アプリを使う (#1021)

ランチャーに **`Open X terminal`** を追加しました。Windows 側の X サーバ
(VcXsrv / XLaunch) に guest の `xterm` を出せます。**ssh も VNC も要りません。**

★ **その端末から起動した X アプリも同じ X サーバに出ます。** 実機で
**X 版 Emacs を日本語入力まで**動かせることを確認しました。

- 押す前に前提 (X サーバが居るか / guest に `xterm` があるか) を確かめ、
  足りない方を**次に何をすればよいかまで**案内します
- guest → host の loopback は既定で遮断されます。このボタンは **X のポートだけ**を、
  そのセッションに限って許可します
- 手順は README の「**guest の GUI アプリを使う (X 端末)**」にあります
  (VcXsrv の導入、XLaunch の設定、`apt install -y xterm` まで)

## guest の `apt install` が 40 分止まるのを直した (#1031)

`x11-apps` などを入れると **man-db が man データベースの全再構築**を始め、実機で
**40 分以上終わらない**ことがありました (`Ctrl-C` も効きません。dpkg が設定中の SIGINT を
無視するため)。出荷 rootfs で**この自動再構築を既定で止めました**。

★ `man <cmd>` はこれまでどおり使えます。効かなくなるのは `apt`/`man -k` の索引検索だけで、
必要なら guest で `mandb` を 1 回走らせれば作れます。

## IPv6 で listen した port が IPv4 を塞ぐ (#1020)

`IPV6_V6ONLY` が効かず、IPv6 で listen すると **IPv4 の同じ port まで塞いで**いました。
sshd の X11 転送 (`ssh -X`) が張れない形で顕在化しました。

## 本体の欠陥

| | |
|---|---|
| **#1024** | native (KVM/WHP) backend が **CPU 例外を vector ごとの signal で配送していなかった**。#GP だけが SIGSEGV として配送され、**#DE が SIGFPE にならない** (0 除算のハンドラが呼ばれない)。#UD→SIGILL / #AC→SIGBUS 等もまとめて是正 |
| **#1028** | exec が「後戻りできない地点」で失敗すると **vfork の親が永久に待つ**。guest 内で gcc を動かすと再現し、38 分放置しても進みませんでした |
| **#1026** | 内部 OOM のあと guest が固まったとき、**黙って止まらず診断を出して落ちる**ようにしました。停止は「遅い」より悪い — 原因が何も残らないからです |

## 検査・診断

出荷物の品質そのものではありませんが、**次の不具合に早く辿り着くため**の改善です。

- **#1018**: `timeout` に殺された検査が「値が違う」に化けるのを、残り 13 本で解消
- **#1026**: 停止時に **JVM のスレッドダンプ**を取る計器 (これで #1026 の原因に到達)
- **#1033**: ssh 軸の失敗で **client 側の言い分**を残す / `ConnectTimeout` を可変に
- **#1024**: native backend の網羅オラクルを回帰網に登録
  (それまで **run-all に "native" の語が 1 つも無く**、native は検査の外に居ました)
- **#1036/#1039**: メモリを多く使う検査を直列化し、CI の偽陽性を止めた

---

## 既知の問題

- **#1036**: software backend の guest メモリが重い (busybox 1 プロセスで 279MB)。
  上の #1026 の停止はこれが原因で、いまは**診断して落ちる**状態です
- **#1033**: CI で ssh の握手が稀に EAGAIN で落ちる (原因未特定)
- **#1040**: 高負荷時に自分宛て signal が届かないことがある (5〜8%、原因未特定)
