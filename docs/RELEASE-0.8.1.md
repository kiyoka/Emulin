0.8.1 は **0.8.0 で露呈した土台の弱さを埋める**リリースです。新機能は
credential サンドボックスへの GitHub トークン追加だけで、残りはすべて
**長時間・大量 fork で壊れないこと**と、**サンドボックスが黙って無効化されないこと**に

エミュレータが OOM したことでした。同じ根の資源解放漏れを潰し、同種の回帰を
自動で捕まえる計測を入れてあります。

## ハイライト

### 1. 長時間・大量 fork で壊れない

0.8.0 では、fork を大量に行うとヒープや vCPU が枯渇してエミュレータごと死んでいました。
**「終了した guest プロセスの資源を解放しない」という同じ形のバグが 3 件**あり、すべて塞ぎました。

- **#886** `FutexManager` の static テーブルと `NativeCpuBackend.forkParent` が終了プロセスを
  解放せず、実機で `-Xmx8g` を使い切っていた (ダンプ 6.9GB のうち 5.5GB が終了済み
  1077 プロセス分)。
- **#889** 親が `wait` せずに終了した子 (孤児) が刈り取られず `ProcessInfo.process` に溜まる。
  実 Linux は init が reparent して回収するので、そこに合わせた。
  → native/KVM で 4000 回の fork: 生存 `Process` が 527→3696 と増え続けていたものが **14〜21 で一定**に。
- **#843** vCPU id が再利用されず、**生涯 4096 スレッドでプロセスが死ぬ**。
  vCPU 「id」ではなくオブジェクトを pool して再利用する形にした。
  → 5000 スレッド完走。`EMULIN_MAX_VCPUS=32` に下げても 2000 スレッドが走る。

★ **指標そのものを見直しました。** この 3 件はどれも、従来の監視指標 (fd 数 / RSS /
スレッド数) では**素通り**していました。RSS は GC と off-heap で鈍く、fd は無関係、
スレッド数は正常値だったためです。full GC 込みの class_histogram から
**生存 `Process` / `MemoryBackend` 数**を採る形に変え、同種の漏れが次からは自動で
捕まるようにしています。

### 2. credential サンドボックスが黙って無効化されない

0.8.0 の通信サンドボックスには、**「効いていないのに動いてしまう」**経路がありました。
利用者から見ると成功と区別が付かないため、これは実質的にセキュリティ機能の不発です。

- **#898** Go 製クライアント (`gh`) で**黙って素通しに縮退**していた。DNS スヌープが
  受信 syscall のうち `read()` 経路を見ていなかったため。
- **#903** guest の CA バンドルが **2 つあり片方しか更新していない**ため、`git` だけが
  MITM 先の証明書を検証できなかった。
- **#900** DNS スヌープの hook を**受信の共通 1 点に寄せた**。syscall 単位に散っていると、
  クライアントが変わるたびに穴が開くため (#898 がまさにそれ)。
- **#907** **縮退したことを終了時に知らせる**ようにした。黙って素通しになる状態を
  既定で検知できる。

★ #898 と #903 は**どちらも「更新すべき場所が N 個あるのに 1 個しか更新していない」**
という同じ形でした。決め手は `[mitm]` のトレースが **1 行も出ない**ことです。

### 3. credential に GitHub トークン (#848)

`gh` / `git push` を guest から使うとき、これまでは実トークンを guest に置くしかありませんでした。
0.8.0 の credential 管理の枠組みに乗せたので、**エージェントに PR を書かせる用途も
実トークンを渡さずに**行えます。

### 4. TLB flush を本来の形に (#885)

0.8.0 の #880 は「WHP で毎 syscall ごとに CR3 を書き直す」という力技で塞いでいました。
これを **MMU 世代カウンタ方式**に置き換えています。

★ 実際に TLB が古くなるのは **present な PTE を外した / 張り替えた**ときだけで、
not-present → present (`#PF` の faultIn) は無効化不要です。しかもこれが最頻経路でした。
→ 実測で、syscall 集中時 40120 回中 flush **52 回 (0.13%)**、長命プロセスで 0.10%
(**従来は 100% = 毎 syscall**)。正しさの保証は #880 と同じです。

### 5. 並列負荷下の 2 つの race

- **#911** Emulin が **`rc=0` のまま標準出力を 1 バイトも出さない**ことがあった。
  `Kernel.processes()` が `synchronized` でなく、`exec()` が process を差し替える途中を
  観測して「もう誰も居ない」と誤判定していた。
  ★ シェル経由で単一コマンドを実行する普通の使い方で、**成功と区別が付かない空の結果**を
  返し得たため、影響はテストに限りません。→ 修正後 980 回で 0 件。
- **#914** `FUTEX_(CMP_)REQUEUE` が**原子的でなく、移送直後の `FUTEX_WAKE` が消える**。
  待機者は永久に起きません。→ 取りこぼし 20/20 だったものが 0/10 に。
  ★ glibc 2.25 以降の新しい condvar は requeue を使わないため今まで踏まれていませんでしたが、
  **musl の `pthread_cond_broadcast` は使う**ので、static-pie の musl バイナリ (codex 等) が
  該当し得ます。

### 6. その他

- **#842** native で `io/pipe` が約 9% の確率で 4096 バイト取りこぼす間欠バグ
- **#852** 非 root で ssh すると `HOME` / `USER` / `LOGNAME` が root のものになる
- **#891** 配布 zip 同梱ドキュメントの陳腐化。README.md との**二重管理を断ち**、
  同梱は `QUICKSTART.txt` だけにして詳細は GitHub の README に寄せた

## 既知の制限

- ★ **#921 Codex は、credential を `setcred` で登録した構成だと、コマンド実行を伴う依頼が
  返りません。0.8.2 で修正して出します。**
  - **症状**: チャット (テキストだけの応答) は正常に返りますが、ファイル一覧の取得など
    **コマンド実行を伴う依頼をすると応答が返らなくなります**。モデルが「コマンドを実行します」と
    答えた直後、**実行指示 (tool call) が届かないまま止まります**。数分待っても返りません。
  - **確認した環境**: Windows 11 / WHP / `emulin.bat sshd` 経由の ssh / codex 0.146.1 と 0.147.0 の両方。
  - **切り分け済み**: エミュレータの凍結ではありません (CPU は動いています)。futex の
    起こし取りこぼしでもありません (診断計器で確認)。**同じコマンドを guest の bash から
    直接実行すると一瞬で返ります**。通信が応答の途中で途切れる形とみています。
  - ★ **`setcred` を使わない構成 (実トークンを guest に置く) で再現するかは未検証**です。
    症状を確認したのは credential サンドボックスを通す構成のみです。
  - Claude Code はこの事象の影響を受けません。
- **#740** 長時間セッションで**稀に凍結**することがあります (数時間に 0〜1 回)。
  0.7.0 から残っている唯一の原因未特定の事象です。観測された形 (V8 の rwlock / condvar) を
  高頻度で叩く再現機を作って 160 実行しましたが再現せず、**単一プロセス内の
  rwlock / condvar / signal の組み合わせでは起きない**ことまでは分かっています。
  診断計器は配備済みで、次に発生したときに「wake 発行済みなのに不起床」か
  「そもそも未発行」かが確定します。
- ビルド済み zip は Windows 用のみです。
