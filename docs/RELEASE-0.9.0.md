## ハイライト

### 1. ★ ランチャー (`emulin-app.bat`) を標準サポート (#948 系列)

解凍して `emulin-app.bat` をダブルクリックすると、状態がひと目で分かる画面が開きます。
**Agents** は「まだ入っていないもの」、**Credentials** は「まだ登録していないもの」を並べ、
あとは必要なボタンを押すだけです。

| ボタン | 何をするか |
|---|---|
| **Install Claude Code** / **Install Codex CLI** | 済んでいる工程を判定し、**足りない工程だけ**実行する。root / 非 root の使い分けは UI が肩代わりする |
| **Set up credentials** | host で済ませたログインを取り込む。登録内容の確認・削除もここ (`emulin.bat setcred` の GUI 版) |
| **Open terminal** | `emulin.bat` 相当を開く (Windows Terminal)。ここで `claude` / `codex` を起動する |
| **SSH server** `Start` / **Add public key** | sshd の起動・停止と、SSH クライアントの公開鍵の登録 |

以前から効いていた判定は同じですが、**「判定は効いていたが見せ方が無かった」**部分を
実機で使いながら潰しました:

- 導入は**工程ごとに実行ユーザーと経過時間**を出します。nodejs/npm の導入は 20 分ほど
  かかるので、「動いている」と「止まっている」を区別できるようにするためです (#961)
- **Open terminal が窓枠に見えて掴まれた**ので、枠と余白を付けて「押せるもの」にしました
- cmd.exe の**黒い窓を 1 つ残していた**のを、`wt.exe` を直接起こす形にしました (#976 / #977)

**初回は非 root ユーザー (uid 1000) の作成を訊きます。** 名前は guest のログイン名・
ホーム・`ssh` のユーザー名になります。**Windows のアカウント名からは補完しません** —
Windows は Microsoft アカウント名からプロファイル名を作るときに末尾を削ることがあり
(`kiyoka` → `kiyok`)、**利用者が選んでいない名前**が既定で入ってしまうためです。
エージェントはこのユーザーの
ホームに入り、**Open terminal もこのユーザーで開きます** — 「入れたユーザー」と
「端末を開くユーザー」が食い違うと `claude` が PATH に無い状態になるためです
(mozc IME など一部アプリが実 Linux と同じく root では動かない、という事情もあります)。

**root の端末は `Open terminal as root` で開きます。** guest に `sudo` は無いので、
`apt install` などはこちらが要ります。**どちらのユーザーで開くかは押したボタンで
決まり**、窓が開いてから訊かれることはありません。

**公開鍵の登録 (#964)** は Windows のホームと **WSL の全ディストリの両方**を探し、種別 /
`SHA256:` 指紋 / コメント / **実ファイルパス**を出して選ばせます。**秘密鍵は中身で判定して
拒否**します (`*.pub` という名前の秘密鍵も弾きます)。登録先は root と非 root の**両方**で、
`[installed]` は**その全部に入っているときだけ**です — root にだけ入った状態を「登録済み」と
出すと、`ssh <user>@` が拒否され続ける理由が画面から分からなくなるためです。

**credential の UI (#968)** は **値を一切表示しません**。登録済み / 未登録、いつ更新したか、
どのエンドポイント向けかだけを出します。取得手順と URL も画面に載っています。

### 2. ★ ランチャーを開いただけで、動いているセッションの認証が切れないように (#955 / #991)

Emulin は起動のたびに guest の credential placeholder を作り直します。そのため
**同じ rootfs で 2 つ目の Emulin を起動すると、動いている claude / codex が
`Login expired` になります**。

0.9.0 では、ランチャーが **同じ rootfs の別インスタンスを検出**し、

- 導入状況の**判定 (自動)** は**行いません**。画面には `[unchecked]` と、
  見送った理由を出します
- **Install / sshd Start** は、押したときに**確認ダイアログ**を出します (既定は「いいえ」)

としました。★ **判定を止めるだけでなく「止めたこと」を画面に出す**のが肝で、
`[checking ]` のままにすると利用者は待ってしまいます。

> 根本原因 (rootfs ごとに placeholder を共有していること) は #955 で引き続き検討中です。
> 0.9.0 で塞いだのは**壊しに行く経路**です。

### 3. 画面の文字列を選択してコピーできる (#988 / #990)

credential の「取得手順」には URL や手順が書いてあるのに、**1 文字も選択できません**でした。
手で打ち直して 404 を踏んだ実例が出たので、**面ごと 1 つのテキストにして、行をまたいで
選択・コピー**できるようにしました。**選択中は 5 秒ごとの再描画を止めます** —
コピーしようとしている最中に選択が消えるのが一番困るためです。

### 4. `Open terminal` の native pool を 1024 にした (#985)

ランチャーから guest を起こす経路のうち、**`Open terminal` だけが pool を渡しておらず**、
`emulin.bat` の既定 2048 のまま動いていました。エージェントは自分の他にシェルやツールを
並行して起こすため、2048 のままだと 32GB 窓に入りきらず software backend に落ちて
**極端に遅く**なります (#379)。しかも**画面には何も出ません**。

0.9.0 では **`Open terminal` と `SSH server` の `Start` がどちらも 1024** を使います。
**自分で `EMULIN_NATIVE_POOL_MB` を設定していれば、その値が優先されます。**

### 5. 認証まわりに残っていた穴 (#970 / #971、#876 / #935 / #980)

- 0.8.5 で入れた refresh の直列化に穴が 2 件残っており、実機で `401` が再発しました。
  **ゲートを持ちすぎる経路**と、**失敗を成功として返す経路**を塞ぎました (#971)
- claude の**初回 onboarding の seed** が、現行のブラウザ OAuth
  (`CLAUDE_ACCESS_TOKEN`) を見ていませんでした。**形は通るのに初回だけログイン選択が
  出る**という、気付きにくい形でした (#980)

### 6. guest から host の localhost 上のサービスへ到達できないように (#949 / #950)

guest 内のプロセスが、host で動いている開発サーバや管理画面へ `127.0.0.1` で
到達できてしまっていました。sandbox の境界として塞いでいます。

### 7. `mkdir("/proc/self/fd/N/...")` が ENOENT になる (#982 / #983)

`/proc/self/fd/N` の解決が**完全一致しか扱えず**、`/proc/self/fd/N/<相対パス>` の形が
通りませんでした。claude CLI 2.1.251 が Bash tool の作業ディレクトリ作成にこの形を
使い始めたため、**その版だけが guest で動かない**状態になっていました
(実 Linux では再現しないので、原因が Emulin 側だと分かるまで時間がかかりました)。

### 8. GitHub token の取得手順を現在の画面に合わせた (#989)

GitHub の PAT 発行が `Settings → Developer settings → Personal access tokens` から
**`https://github.com/settings/credentials`** に変わっていました。fine-grained と classic の
どちらでもよいこと、必要な権限、`gh auth setup-git` が要ることを画面と README に書きました。

### 9. README をランチャー前提に簡略化 (#986)

「ボタンを押せば済むこと」を本文に、「なぜ・細部・落とし穴」を折りたたみに分けました。
スクリーンショットを入れ、SSH サーバの節も `Start` / `Add public key` の手順に置き換えて
あります。**セキュリティに効く注意 (guest の中で `/login` しない、`CLAUDE_CONFIG_DIR` を
省かない) は畳まずに本文に残して**います。

## 既知の制限

- **#740 (稀な凍結)** … 0.8.1 から引き続き未解決です。V8 の rwlock/condvar 待機者が
  プロセス内で起こしを失う事象で、原因未特定です。
- **#955 (根本原因)** … 同じ rootfs で 2 つ目の Emulin を起動すると、動いている
  guest の credential が壊れます。0.9.0 は**ランチャーからその経路に入らないように**
  しましたが、`emulin.bat` を 2 つ手で起動した場合は依然として起こります。
- **#969 (ログ欄の日英混在)** … ランチャーのログ欄に日本語と英語が混ざります。
- **`mincore` の backend 差** … software backend は匿名メモリを eager に確保するため、
  **未 touch のページも「常駐」と答えます** (native backend は Linux どおり 0)。
  修正には hot path にコストが乗るため、**既知の制約として修正しません**。
